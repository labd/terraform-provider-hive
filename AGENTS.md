# AGENTS.md — terraform-provider-hive

Terraform provider for [GraphQL Hive](https://graphql-hive.com/) written in Go.
Module: `github.com/labd/terraform-provider-hive` | Go 1.24.0

## Build / Test / Lint Commands

This project uses [Task](https://taskfile.dev/) (v3) instead of Make. All commands
are defined in `Taskfile.yaml`.

```sh
# Run all tests
task test                    # go test -v ./...

# Run a single test by name
go test -v -run TestFunctionName ./internal/provider/...

# Run tests in a specific package
go test -v ./internal/sdk/...

# Run tests with race detection + coverage (as CI does)
go test -race -coverprofile=coverage.out -covermode=atomic -coverpkg=./... -v ./...

# Acceptance tests (requires TF_ACC=1)
TF_ACC=1 go test -v ./...

# Lint
golangci-lint run --timeout=5m

# Format
task format                  # go fmt ./... && terraform fmt -recursive -write=true ./examples/

# Generate GraphQL client + Terraform docs
task generate                # go run github.com/Khan/genqlient && go generate ./...

# Build for local dev (installs to ~/.terraform.d/plugins/)
task build-local

# Coverage with HTML report
task coverage-html
```

## Project Structure

```
main.go                          # Entrypoint (providerserver.Serve)
internal/
  client/
    generated.go                 # AUTO-GENERATED by genqlient — do NOT edit
    genqclient.graphql           # GraphQL operations (queries/mutations)
  sdk/
    client.go                    # HiveClient, HiveRoundTripper
    schema_check.go              # SchemaCheck business logic
    schema_publish.go            # SchemaPublish business logic
    app_create.go                # CreateApp business logic
    app_publish.go               # PublishApp business logic
    git.go                       # Git commit info extraction (go-git)
    utils.go                     # Schema minification, target helpers
    debug.go                     # HTTP debug logging transport
  provider/
    provider.go                  # HiveProvider definition
    resource_*.go                # Terraform resources
    data_source_*.go             # Terraform data sources
  utils/
schema.graphql                   # Full Hive API schema (genqlient input)
genqlient.yaml                   # genqlient configuration
examples/                        # Terraform example configs (used by tfplugindocs)
docs/                            # Auto-generated provider docs — do NOT edit
```

### Architecture Layers

1. **client/** — Auto-generated typed GraphQL client (genqlient). Never edit `generated.go`.
   To add/change GraphQL operations, edit `internal/client/genqclient.graphql` then run `task generate`.
2. **sdk/** — Business logic wrapping the generated client. Methods on `HiveClient`.
3. **provider/** — Terraform plugin framework resources/data sources. Uses sdk layer.

## Code Style Guidelines

### Formatting and Linting

- Format with `go fmt` (enforced by `gofmt` linter).
- Linter config: `.golangci.yml` — uses `disable-all: true` with an explicit allow-list.
- Enabled linters: `durationcheck`, `errcheck`, `copyloopvar`, `forcetypeassert`,
  `godot`, `gofmt`, `gosimple`, `ineffassign`, `makezero`, `misspell`, `nilerr`,
  `predeclared`, `staticcheck`, `tenv`, `unconvert`, `unparam`, `unused`, `govet`.
- `godot` is enabled: all exported comments must end with a period.

### Imports

Group imports in three blocks, separated by blank lines:

1. Standard library (`context`, `fmt`, `net/http`, etc.)
2. Third-party packages (`github.com/hashicorp/...`, `github.com/Khan/...`, etc.)
3. Internal packages (`github.com/labd/terraform-provider-hive/internal/...`)

Example:
```go
import (
    "context"
    "fmt"

    "github.com/hashicorp/terraform-plugin-framework/resource"
    "github.com/hashicorp/terraform-plugin-framework/types"

    "github.com/labd/terraform-provider-hive/internal/sdk"
)
```

### Naming Conventions

- **Resources**: Type `Hive<Name>Resource` with model `Hive<Name>ResourceModel`.
  Constructor: `NewHive<Name>Resource() resource.Resource`.
- **Data sources**: Type `Hive<Name>DataSource` with model `Hive<Name>DataSourceModel`.
  Constructor: `NewHive<Name>DataSource() datasource.DataSource`.
- **SDK input/result**: `<Action>Input` and `<Action>Result` structs (e.g., `SchemaCheckInput`, `SchemaCheckResult`).
- **SDK methods**: Named as verbs on `*HiveClient` (e.g., `SchemaCheck`, `CreateApp`, `PublishApp`).
- **Terraform type name**: Set in `Metadata()` as `req.ProviderTypeName + "_snake_case_suffix"`.
- Struct tags use `tfsdk:"snake_case"` for Terraform models.

### Error Handling

- **Provider layer**: Use `resp.Diagnostics.Append(...)` and `diag.NewErrorDiagnostic(summary, detail)`.
  Check `resp.Diagnostics.HasError()` after reading plan/state and return early.
- **SDK layer**: Return `(result, error)` tuples. Use `fmt.Errorf` with `%w` for wrapping.
  Log errors with `tflog.Error(ctx, ...)`.
- **Resource ExecuteRequest pattern**: Each resource has an `ExecuteRequest` method that calls
  the SDK and returns `*diag.ErrorDiagnostic` (nil on success). Called from both Create and Update.

### Interface Compliance

Use compile-time interface checks at package level:
```go
var _ resource.Resource = &HiveSchemaCheckResource{}
var _ resource.ResourceWithImportState = &HiveSchemaCheckResource{}
```

### Resource Patterns

- All resources use `RequiresReplace()` plan modifiers — attributes are immutable.
- `Delete` methods are no-ops (these are action-based resources, not CRUD).
- `Read` methods preserve state as-is (no remote read).
- `ImportState` uses `resource.ImportStatePassthroughID`.

### Types

- Terraform models use `types.String` from `terraform-plugin-framework/types`.
- Convert with `.ValueString()` (read) and `types.StringValue(...)` (write).
- SDK structs use plain Go types (`string`, etc.).

## Code Generation

- **`internal/client/generated.go`** is auto-generated by genqlient. NEVER edit manually.
- To modify GraphQL operations: edit `internal/client/genqclient.graphql`, then `task generate`.
- Schema source: `schema.graphql` (root). Update this when the Hive API changes.
- **`docs/`** directory is auto-generated by tfplugindocs. NEVER edit manually.
  Run `task docs` to regenerate. Docs pull from code + `examples/` directory.

## CI/CD

- GitHub Actions (`.github/workflows/tests.yaml`): runs on every push.
- Tests run with `TF_ACC=1` and race detection.
- golangci-lint runs but is non-blocking (`continue-on-error`).
- Releases use GoReleaser (`.goreleaser.yml`) with GPG signing.
- Changelogs managed by [Changie](https://changie.dev/) (`.changie.yaml`).
